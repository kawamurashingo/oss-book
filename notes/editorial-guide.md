# 執筆・編集ガイド

- 対象：技術書典で頒布する日本語のOSS開発体験記。チュートリアル化しすぎない。
- 視点：基本は著者の一人称「私」。断定的でない落ち着いた語り口。
- 本筋：使う → 作る → 使われる → 守る → 引き継ぐ → 人を育てる。
- 誇張した「成功譚」や、実際には語られていない感情・会話を捏造しない。
- 公開記録から判明した事実と、著者本人への聞き取りと、編集的考察を区別する。
- 技術情報にはバージョン、日付、根拠を付ける。年月日はJST/UTCを混同しない。
- CPAN Rescueの方向転換は、引き継ぎ経験の**後**に生じた気づきとして描く。
- 技術的配当の発想は**職務上の経験**から生まれたもので、CPAN Rescueから派生したものではない。
- 低頻度機能をむやみに増やすことより、互換性と継続可能性という軸を尊重する。
- 初稿は完成原稿ではない。重複と一般論の多さを減らし、場面の密度を上げる。
